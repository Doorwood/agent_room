# 个人飞书文档补写

版本：1.0.11。Host 和发送者客户端均需要升级并重启；1.0.10 不含此功能。

发送者可以说：“把准备好的正文补充到这份飞书文档末尾：<https docx URL>”。Host 通过本轮绑定发送者的 `personal-append` 接收 `{target,title,content}`，不接受账号、凭据、任意命令、覆盖模式或新建替代文档。仅支持明确的 HTTPS docx 链接，不解析 wiki 或任意 URL。

客户端显示目标 URL、完整正文及“末尾追加，保留原内容”。即使已授权自动创建，每次补写仍需核对本机账号并确认此请求；不会借用其他成员或 Host 的账号。Host 校验回执的请求 ID、目标、动作、正文 SHA-256 和发送者绑定。

客户端调用本机 lark-cli，以 user 身份先读取目标，再使用固定的 docs +update append 命令写入。正文逐行转义为纯文本段落，不执行其中的 XML、图片嵌入或文件导入。写入前如已存在完整正文则仅核验，不再追加。该检查将空白归一化；它不是远端原子并发控制，其他客户端同时追加相同内容仍可能产生重复，团队应避免同时补写。

写入前持久化请求占位；同一请求的重复调用返回原回执。错误、取消、部分写入或验证失败保持 unknown，不自动重试。已有内容不会被覆盖。写入后读取全文并检查目标正文确实存在，只有验证通过才能返回 completed。创建操作也增加正文回读验证，防止仅拿到文档链接就报告完成。

客户端单次飞书 CLI 上限由 35 秒调整为 120 秒，自然语言文档操作总上限为 4 分钟。原请求结束、断连、模式切换或撤销授权仍会取消执行，已经发生的外部写入不能撤回。模型必须等待原命令回执，不应为等待授权而主动结束模型轮次。

资源授权面板增加最近 10 次本机文档回执，显示时间、标题、状态、URL 与请求 ID。仅从成员本机私有回执数据库读取，不将账号凭据或原始 CLI 输出传给 Host。旧版本 completed 回执未做正文验证，查看时需明确区分。

限制：使用完整文档读取，CLI 输出仍受 48 KB 安全上限约束；过大文档无法完整核验时拒绝盲目补写或保持待核实。不提供覆盖、段落替换、文档删除、跨端原子去重或自动恢复未知写入。

验证：本地模拟 CLI 覆盖空正文、部分写入、权限失败、账号变化、重复请求；Broker 覆盖发送者与目标、正文摘要绑定；客户端覆盖不能复用创建许可；浏览器检查目标展示与显式确认。未使用 Host 飞书凭据，未对真实飞书文档执行补写。
