# 成员权限与聊天连续性优化（1.0.6）

本次优化 1.0.5 体验报告中的附件展示、草稿恢复、停止含义三个问题，并加入参观者和询问者。纳入 1.0.6 版本。

## 用户可见变化

- 上传后的文件以附件卡片展示，图片可预览，文件可点击下载。同一 room 的获批成员通过 host 校验后读取附件；文件不是浏览器可任意读取的 host 路径。刷新后预览通过 host 恢复，不再只依赖临时 blob URL。
- 草稿按 host、完整 session、成员身份保存到本机私有配置目录，支持刷新、重新连接和重启客户端后恢复。普通聊天和询问者提问分别保存输入内容；不同 room、不同身份不混用草稿。保存成功或失败有提示。
- “停止模型”改名为“停止当前任务”，常驻说明排队任务会继续执行。展示待执行任务及当前任务数量，排队中的占位回复不再标记为执行中。本次没有新增取消队列任务或暂停整个队列。
- 所有可查看主聊天的角色可以搜索已同步的完整历史，并继续分页查看搜索结果。

## 权限矩阵

| 操作 | roommate（协作成员） | visitor（参观者） | asker（询问者） |
| --- | --- | --- | --- |
| 查看、搜索主聊天及历史附件 | 可以 | 可以 | 可以 |
| 提交主任务、笔记、补充、中断、恢复、查看项目 diff/队列 | 可以 | 不可以 | 不可以 |
| 上传附件给主任务 | 可以 | 不可以 | 不可以 |
| 只读询问当前 Codex 会话 | 不可以 | 不可以 | 可以 |
| 查看问答视图 | 查看此 room 所有询问者记录 | 不可以 | 只看自己的记录 |

权限由 host 分配，客户端不能自选或提高权限。现有成员升级后保持 roommate。主流协议每个请求重新查询角色，上传提交时再校验权限，问答和下载也走证书固定的 TLS 与成员审批。

host 审批示例：

```sh
agent_room requests
agent_room approve REQUEST_ID --role visitor
agent_room approve REQUEST_ID --role asker
agent_room approve REQUEST_ID --role roommate
```

修改已批准成员：

```sh
agent_room role REQUEST_ID --role visitor
```

支持 `--state DIR` 指定 host 状态目录。修改角色会关闭该成员的既有连接，重连后刷新界面；旧页面或直接构造请求均不能绕过 host 校验。角色调整不会追溯取消之前已获准提交的工作。

## 询问者问答：复用 Codex 会话

按最新需求调整：不再调用独立的 Responses API，不再需要 `AGENT_ROOM_ASK_API_KEY` 或 `AGENT_ROOM_ASK_MODEL`。Host 使用已有 Codex App Server、登录、模型和原 thread ID 处理询问者的问题，不创建另一个 Codex session。

这是显示区域和权限的区分，**不是模型上下文隔离**。问题和回答会留在 Codex 原 session 中，后续模型能看到，也可能在后续回答中引用；不能承诺不影响模型记忆或其他成员通过模型获知其内容。界面会明确说明这一点。

### 页面和数据流

- 默认主聊天不显示询问者问答。切换“询问者问答”才展示；roommate 可按成员筛选记录，询问者只可查询自己的问答记录。参观者继续只能查看、搜索主聊天。
- 问题和回答保存在 `private/questions.db`，不进入 Room 主聊天的持久或实时事件流。该库只是展示与审计存储，并不是独立模型 session。
- 同一 Host 同时处理一个问答。主会话有任务或正在恢复时拒绝启动问答，提示稍后重试。问答期间新提交的正式任务可以排队，但不会与问答并发执行。
- 重复请求 ID 不会重复调用模型。客户端取消或撤权时尝试中断问答；必须收到结束事件后才允许队列继续，不能把“中断请求已发送”当作“已经停止”。
- 发起问答前持久化当前 thread 的历史边界；结束后记录问答 turn ID。恢复时在写入主聊天之前排除问答 turn，包括启动回复丢失的情况。未知问答仍显示为执行中时暂停恢复，不把它当作正式任务自动续跑。

### 项目只读边界

每个问答 turn 强制使用 `sandboxPolicy.type=readOnly`、`approvalPolicy=never`，本地工具网络访问默认关闭。现有 RPC 层拒绝文件/命令审批、权限提升和客户端工具执行请求。提示词另外明确：只能回答和解释，不安排工作，不安装、不构建、不执行测试、不修改项目；问答中的工作指令也不得在后续正式任务中自动执行。文件写入约束来自 Codex 沙箱，不能仅依赖提示词。

**兼容性限制：MCP、Apps、插件、Hooks 等扩展不一定受文件沙箱约束。** 当前实现检查项目有效配置和当前 thread 已加载的 MCP；配置存在这些扩展、检查失败或响应不完整时拒绝问答，并给出原因，不回退到普通工作权限。这类 Host 尚不能直接使用问答；后续需要增加按轮关闭扩展的可靠能力。不会自动修改用户 Codex 配置或关闭主流程依赖的工具。

后续正式任务仍通过原 StartTurn 路径显式设置自己的工作权限，避免继承问答的只读设置。正常的 Codex 会话记录和 Agent Room 审计状态仍会保存；“项目只读”指模型不得修改项目文件与业务数据，不意味着应用完全不写任何状态。

协议依据 [OpenAI Docs：Codex App Server](https://learn.chatgpt.com/docs/app-server)，并用本项目支持的 Codex 0.153.4 本地 JSON Schema 核对 `turn/start`、`config/read` 和 `mcpServerStatus/list`。逐轮权限设置会成为该 thread 后续默认值，所以正式工作轮必须显式指定自己的权限。

## 数据升级和兼容性

schema 3 增加成员角色表；schema 4 增加问答历史边界和私有 turn 标记。迁移保留旧消息和成员。旧 Host 不理解新权限和问答隐藏标记，因而明确拒绝打开更新后的数据库。升级前备份 Host 状态目录，不能对已迁移目录直接回退旧版本。

角色、问答视图及只读执行需要新版 Host 和客户端。发布安装不自动重启或替换正在运行的 Host。

## 验证范围

测试覆盖：同一 thread 的只读请求参数、后续正式工作权限、不安全扩展配置拒绝、串行执行、取消后等待结束事件、问答不进入主事件流、恢复时跳过问答、启动回复丢失后的历史隐藏、共享 runner 无额外 API key、按身份查看及请求去重。

浏览器覆盖主聊天/问答切换、参观者只读搜索、询问者提问和 roommate 查看，以及之前的附件、草稿、停止任务流程。模型与 App Server 使用受控模拟器；未发起真实模型请求，未完成真实 Codex 工具写入阻断或 macOS/Safari 的实机验收。
