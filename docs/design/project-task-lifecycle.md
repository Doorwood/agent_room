# 项目任务生命周期（本轮实现）

一个 Room 服务一个项目；项目中可以建立多个任务。任务作为需求、执行记录和验收结果的入口，继续使用现有共享模型会话和工作目录。

## 使用方式

1. 协作成员在主聊天的用户消息或模型回答上点击「转为任务」，填写标题和可选的验收标准。
2. 转换只保存任务与来源的关联，不重新发送原消息；同一条工作消息和它的模型回答会定位到同一个任务。
3. 打开「项目任务」，查看任务状态、来源、执行记录、模型回答和变更记录。
4. 检查结果后点击「标记任务完成」。模型执行结束仅表示「待验收」，不会自动完成项目任务。
5. 后续有补充工作时，在任务详情输入要求并「发送到此任务」。已完成任务须先「重新打开任务」。补充工作在共享队列中执行，保留先前记录。

查看另一个任务不改变当前执行目标。主聊天输入框仍提交普通消息；任务详情的输入框明确提交给所选任务，两处草稿分开保存。任务补充也支持 Enter 发送、Alt+Enter 换行。

## 状态与权限

| 状态 | 含义 | 可以标记完成 | 可以追加执行 |
| --- | --- | --- | --- |
| 待处理 | 从笔记建立，尚无模型执行 | 是，支持人工处理事项 | 是 |
| 排队中 | 关联消息在共享队列中 | 否 | 否 |
| 处理中 | 模型正在执行 | 否 | 否 |
| 需要确认 | 正在提交，或此前提交结果不确定 | 否 | 否，先由 Host 处理原有恢复流程 |
| 待验收 | 最近一次执行成功结束 | 是 | 是 |
| 已中断 / 异常 | 最近一次执行未成功结束 | 否 | 是 |
| 已完成 | 协作成员明确验收完成 | 已完成 | 先重新打开 |

协作成员可转换、完成、重新打开和追加任务；参观者与询问者只能查看任务。权限在本机 HTTP、Host 接口和数据库写入处校验。询问者的问答不作为任务来源，也不会进入任务执行记录。

## 数据与兼容

- SQLite schema 5 新增任务、关联消息、变更记录和幂等回执；任务编号在 Room 内递增。
- 不批量转换旧消息，也不改变原有消息序号。任务、关联关系和完成记录在 Host 重启后保留。
- 完成及重新打开校验任务版本；同一请求重试不会重复修改。任务补充与消息接收在同一事务中提交，失败时不留下孤立消息。
- 队列恢复会恢复任务关联；Host 的「继续处理」恢复命令产生的替代消息仍归属原任务。
- 网络新增 `tasks` 查询/修改操作与 `task_submit` 消息方法。旧 Host 会拒绝不支持的操作，避免将任务补充静默当作普通消息执行。使用新功能需要同时更新 Host 和客户端，并重启相应进程。
- 列表每页 50 个任务，详情每页至多 10 次执行；可继续加载更早记录。详情显示最近 50 条变更，每次执行显示至多 64 KiB / 100 条模型输出，超出时提示到主聊天查看完整历史。
- 主聊天和询问者问答显示日期与时分秒，按浏览器本机时区展示；旧记录没有时间时显示「时间未知」，不补造历史时间。

## 本轮边界

这是任务跟踪、追加执行和人工完成的闭环。共享会话与目录保持现有行为，尚不提供任务独立 worktree、上下文隔离、Reviewer 指派、不可变文件差异快照或强制项目级验收门禁。不同任务仍按现有共享队列顺序执行；任务验收不会阻塞其他已排队工作。

任务详情引用现有消息和 turn 记录。需要人工恢复的原消息重试仍沿用已有恢复语义，不将每个重试尝试改造为独立不可变 Run；完整异常过程保留在主聊天历史中。
