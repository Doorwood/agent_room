# Room 资源授权与个人资源问答

版本：1.0.8。提供受控的只读资源调用、个人身份创建飞书文档和发送者署名的本地 Git 提交；不包含评论、文档更新、推送或删除操作。

## 使用方法

Host 在项目目录执行：

```sh
# 查询当前项目的资源授权方式，初始值为 host
agent_room resource-mode

# 切换为访问者各自的本机身份
agent_room resource-mode personal

# 恢复使用 Host 的资源身份
agent_room resource-mode host
```

可用 `--state DIR` 指定项目状态目录。只有能访问 Host 私有管理 socket 的本机管理员能切换；远端成员不能修改。配置按项目持久化。切换前需要停止或等待当前模型任务结束，避免同一轮混用账号；切换会中断资源请求并使旧创建凭证失效。

使用者更新、重启客户端并连接 Room 后，在聊天上方点击「资源授权」：

1. 查看 Room 当前资源授权方式。
2. 个人模式下，在自己的终端完成工具登录，点击「开启本机个人授权」。读取本机项目文件时填写项目绝对路径；该路径只保存在本机窗口的运行状态中，不发给 Host。
3. 选择读取操作，填写资源位置／搜索词。问题留空时仅返回原始资源；填写问题时由 Host 独立临时模型回答。
4. 核对弹窗中的身份、操作与资源后确认执行。
5. 可随时点击「撤销本机授权并停止调用」。撤销针对当前 Room 的本地代理，不会注销 GitHub／飞书 CLI 自身的登录。
6. 通过此资源面板读取的结果默认只在当前用户窗口内展示。不写入主聊天、询问者公共查看列表、项目任务或历史数据库。读取结果刷新后不保留；创建回执在本机持久保存；关闭页面本身不是撤销授权，关闭对应 Room 连接或退出客户端会释放该窗口授权。

Roommate 可明确选择内容带到主聊天草稿；已有草稿不会被覆盖，仍需手动发送。发送之后才属于共享内容。

## 首批资源操作

| 操作 | 资源位置 | 范围 |
| --- | --- | --- |
| GitHub 仓库信息 | `owner/repo` | github.com，GET |
| GitHub 未关闭 Issues | `owner/repo` | 最多 20 条，不自动翻页 |
| GitHub Issue | `owner/repo#123` | 单个 Issue |
| GitHub Issue 搜索 | `owner/repo` 与普通关键词 | 指定仓库，最多 20 条，不支持扩展查询限定符 |
| 飞书文档读取 | 文档链接或 token | docx／wiki，用户身份 |
| 飞书文档搜索 | 搜索词 | 用户可访问文档，最多 10 条 |
| 项目文本文件 | 相对路径 | 个人模式使用用户选定目录；Host 模式使用 Host 项目目录 |

单次结果上限为 48,000 字节；不默默截断。项目文件必须为普通 UTF-8 文本，路径不能逃逸授权目录，不接受隐藏路径或依赖目录。此接口不是任意 shell、HTTP、GraphQL 或 MCP 代理。

GitHub 使用 GitHub CLI，用户在本机执行：

```sh
gh auth login --hostname github.com --web
```

飞书使用已经安装、配置好的 lark-cli：

```sh
lark-cli auth login --domain docs --domain drive
```

调用固定使用 `--as user`，不会改用 bot。CLI 管理自己的登录凭据，agent_room 不提取或传输 token。若系统的 `gh` 是其他同名工具，本机启动客户端或 Host 前可设置 `AGENT_ROOM_GITHUB_CLI` 为真正的 GitHub CLI 路径；此选项不接受网络输入。

## 直接发消息创建飞书文档

个人模式下，Roommate 直接发送「创建一个 XX 飞书文档」。模型在原有主会话准备标题和正文，通过本轮专用 `personal-create` 命令请求创建，不需要用户点击每条回复的创建按钮。

1. Coordinator 将已认证的发送者 Actor 直接传给创建路由，不解析消息中的昵称、participant 标记或模型提供的 UID。排队消息、项目任务后续消息均绑定各自的本次发送者。
2. 每轮生成独立随机凭证，专用命令只接受标题、正文和本轮凭证。服务端同时核对发送者的协作角色、消息归属和任务正在执行的状态。后续轮次、取消、角色变更或授权模式变更使旧凭证失效。
3. 请求只交给发送者的一个已认证客户端实例；同一身份的第二个客户端不能抢占。断线后不会把可能已执行的请求交给其他机器再次创建。
4. 没有本机创建授权时，发送者的 Room 页面自动弹出授权请求，显示标题、可展开核对的完整正文及本机登录方法。点击「核对本机飞书账号」，确认实际姓名和 Open ID 后「授权我的账号并继续」。不向其他成员询问、不索要密钥，也不在 Host 登录。
5. 已授权时自动执行；本次连接中，该用户之后要求新建的文档无需重复确认。每次执行仍检查当前飞书账号是否与授权账号一致，账号变更、过期或权限不足会暂停并请求本人重新授权。参观者、询问者不能使用创建通道。
6. 创建回执返回主模型，模型在当前任务回复创建者及文档链接。与资源面板的私人读取结果不同，这条自然语言工作流程的文档正文和结果属于主模型任务上下文；成功链接可以出现在公共聊天。

授权仅保留在本机 Room 连接内存中。关闭浏览器页面本身不撤销授权；撤销本机授权、关闭 Room 连接或退出客户端后需要重新授权。模型命令最多等待 5 分钟，超时或取消后不再派发未开始的请求；已经发往飞书的写入无法撤销，须核对本机回执。客户端在创建期间监测请求、连接和角色，失效即停止本机进程，不自动回退或重试。

个人模式下，终端 `steer` 补充要求暂时拒绝，应发送新消息排队，以免一轮中混入另一人的创建要求。普通主聊天发送、项目任务继续和停止当前任务均保留。

## 使用发送者署名提交代码

个人模式下，发送「优化 XXX 代码并提交」等明确提交要求后，模型使用专用 `personal-commit` 命令；仅要求优化、修复代码不自动提交。该命令接受提交说明、明确的相对文件列表和预期 HEAD，不接受模型指定的作者、仓库路径或用户身份。

第一次提交时，发送者自己的 Room 页面询问 Git 姓名和邮箱。确认后，Author 和 Committer 均采用该署名，不修改 Host 或仓库的共享 Git 配置。该身份仅存在于本机 Room 连接内存中，与飞书授权独立；后续本人明确要求的提交复用署名，撤销本机授权或关闭连接后重新询问。其他用户、客户端不能替发送者确认。这里记录的是发送者确认的 Git 元数据，不是经 GitHub 验证的身份，也不是个人密钥签名。

Host 在授权前为指定文件生成不可变的工作区快照，展示分支、基础 HEAD、快照哈希、文件列表和变更统计。提交使用这个快照，保留其他文件已有的暂存内容；快照生成后的工作区修改仍留在工作区。当前按整个文件提交，不能隔离同一文件中不同成员的修改或选择部分变更块，模型提交前必须核对文件范围。等待期间分支、HEAD 或索引发生冲突时拒绝提交。项目目录必须是仓库根目录，暂不支持 detached HEAD、子模块变更及正在进行的 merge/rebase/cherry-pick。

执行仍绑定已认证发送者和活跃消息的每轮凭证，取消任务或撤销权限会使凭证失效并取消进行中的 Git 命令；已经创建的提交不会自动撤销。Host 用独立临时索引构建提交，以 `update-ref` 比较预期 HEAD 后更新分支，持久化回执避免同一请求重复提交；崩溃、超时或无法确定结果时保留「待核实」，不自动重试。Git 分支和索引的更新不是跨文件事务，异常退出后需检查两者状态。

此入口只创建本地未签名提交，不执行 Git hooks，模型应在提交前完成项目要求的检查。1.0.10 新增独立的个人 GitHub 推送通道，需本人逐次核对账号与目标，详见[个人 GitHub 推送](personal-github-push.md)。不能借用 Host 的 GitHub、SSH 或签名凭据。自然语言提交与文档创建一样依赖每轮路由指令，专用命令有身份校验，但不是任意 Host Shell 命令的系统级拦截。

## 手动使用自己的飞书创建新文档

仅个人模式的 Roommate 可以创建。聊天中模型最终回复提供「用我的飞书创建」，也可在「资源授权」中选择「使用我的飞书账号创建文档」。入口使用本次点击者所在客户端的已登录飞书用户，不凭 Room 昵称猜测飞书账号，也不自动采用原问题作者的账号。

开启本机个人授权后，填写标题、核对完整正文，再核对本机 `whoami --as user` 返回的姓名与 Open ID 并确认创建。客户端执行前再次验证账号与确认时一致；调用固定为 `docs +create --as user`，不回退 Host 或 bot。正文以转义后的纯文本段落写入，不解析模型提供的 XML，不读取图片、文件或嵌入资源。标题最多 240 字节，正文最多 24,000 字节。暂不支持指定目录或转移所有权。

创建后返回可点击的新文档链接。Host 接收本次标题、正文和不含凭据的创建回执，不保存个人 token；原始 CLI 输出不透传。通过手动入口创建不调用总结模型，也不自动向主聊天发布链接。

客户端按 Room 和本机访问身份保存私有 SQLite 回执（操作 ID、内容摘要、标题、账号、结果和链接），在外部写入前先持久化占位。同一操作 ID 不会再次创建；改动请求内容不能复用原 ID。浏览器当前会话保存最近一次请求正文和 ID，用于重复点击去重和查询本机回执。超时、退出或不完整响应标记为「待核实」，可能已经创建，不能视为失败后自动重试。即使取消连接，也无法撤销已到达飞书的写入。应先查询本机回执或在自己的飞书中检查。

## 身份与连接约束

- TLS 证书指纹沿用 Room Session，调用前必须经过成员审批。
- 发起用户由经过认证的连接确定，请求体不接受 UID、令牌、环境变量或可执行程序。
- Host 模式使用 Host 的工具登录；个人模式只向本次发起连接请求执行。
- 本机只接受与刚确认的操作、目标、搜索词，以及创建标题、正文、账号、请求 ID 完全相同的一次执行请求。扩大目标、切换模式、重复执行均拒绝。
- 本机未开启授权、失联、工具未登录或无权访问时失败，不回退 Host 身份。
- 同一成员同一时刻一个资源请求，整个 Host 最多四个；调用有超时。断开、撤销成员、改变角色、切换模式会中断正在进行的连接。
- 参观者不能发起资源调用。询问者只能在个人模式下执行这批只读操作，不能使用 Host 的资源账号、安排工作或通过此入口分享至主聊天。Roommate 可使用两种模式。
- 本机授权只存于该 Room 窗口的内存中，不会在重启后自动开启。

## 模型与数据隔离

资源读取由 Host 发起受控请求，个人客户端在自己机器运行固定 CLI／文件读取，再经同一 TLS 连接返回结果。Host 不将这些结果持久化到 Room 数据库，但会在内存中处理它们；填写问题意味着同意将内容交给模型服务。

隔离问答启动独立 Codex App Server 进程，使用临时工作目录、临时 CODEX_HOME、独立 ephemeral thread。只链接 Host 自己已有的 auth.json，模型仍使用 Host 登录；不复用主线程、项目配置、主线程标识或个人工具密钥。禁用 Shell、扩展和记忆，核验配置及 MCP 列表后才传入资源内容。退出时清理临时目录。

当前依赖 Host 的文件型 Codex 登录和支持 ephemeral thread 的版本；仅有系统钥匙串登录或自定义 provider 配置的环境可能无法完成总结。不会复制这些环境的完整配置或回退主会话；仍可查看已读取的原始资源。隔离进程使用最小配置下的模型默认值，不自动继承 Host 的模型／provider 自定义设置。

隔离只意味着不进入 agent_room 主聊天及主模型会话，不承诺模型服务端零保留，也不能让不受信任的 Host 管理员无法看到调用结果。

## 明确的当前边界

`resource-mode` 控制的是上述新增资源通道，**不是对 Host 操作系统账号的全面降权，也不会自动截获主会话已有的 Shell、MCP、插件或第三方 CLI 调用**。主会话原有执行环境不受此设置改变。

自然语言新建飞书文档已通过模型每轮的路由指令接入专用个人创建命令，旧会话也会在下一轮收到指令，不需要新建 Codex session。该命令强制校验发送者绑定并由个人客户端执行，无 Host 代建分支。它不是对任意 Host Shell／MCP 的系统级拦截：模型遵循路由指令是正常工作流前提，不承诺对绕过路由的任意主机程序实施账号隔离。其他个人工具的自动路由、其他写操作和任意工具透明转发仍需独立设计。

## 验证

- 单元／集成：读取白名单、路径边界、身份隔离、不写共享历史、模式持久化、缺失授权不回退、切换中断、越权目标及重复请求拒绝。
- 创建：固定用户身份、账号变化拒绝、账号隔离、纯文本转义、并发及重启去重、超时不重试、Host／询问者／参观者拒绝写入、请求篡改及伪造成功拒绝。
- 自然语言创建：认证 Actor 与正文解耦、排队发送者正确绑定、专用 CLI/Unix HTTP 传输、跨用户和跨客户端拒绝、旧凭证拒绝、账号变更后重新授权、取消和角色变更停止派发。
- Git 提交：临时真实仓库验证 Author／Committer、两名发送者依次提交、保留其他暂存内容、快照后的工作区修改、初始提交及增删文件、HEAD／索引变化拒绝、持久化去重、跨用户和命令字段伪造拒绝；浏览器模拟模型验证首次确认、复用、撤销、拒绝和仅修改不提交。
- HTTP：精确同源确认、拒绝密钥等未知字段、撤销中断。
- 模型：模拟 App Server 验证独立进程／线程、配置核验、拒绝不安全配置、不继承共享线程标识。真实本机 Codex 0.153.4 仅做无模型生成的协议握手验证：ephemeral=true、Shell 关闭、MCP 列表为空。
- 浏览器：读取前开启授权和逐次确认、取消、个人展示、主动带入草稿、撤销、移动端布局；自然语言首次授权、后续自动创建、撤销后再次询问和拒绝不创建。
- 开发测试使用虚构资源、模拟模型和假飞书 CLI，不访问真实个人 GitHub／飞书资源、不创建真实文档，也未执行真实模型生成；浏览器测试验证流程，不能替代发布后的真实账号试用。
