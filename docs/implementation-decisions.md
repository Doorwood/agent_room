- Ruling: Task 4 follows the pinned generated schema and official App Server transport rather than the plan's earlier generic JSON-RPC envelope — omit and reject the `jsonrpc` member, allow `trace` only on server requests, and allow `emittedAtMs` only on notifications — empirical cost if wrong: the pinned binary's real responses would otherwise terminate every session immediately. Plan corrected in commit `23e8b60`.
- Ruling: Task 4 sends `clientInfo.name = agent_romm` and validates the first initialize `userAgent` token as exactly `agent_romm/<accepted-cli-version>` — the pinned binary derives that token from the integration name when no internal originator override is present, and official documentation requires integrations to identify themselves — cost if wrong: a changed upstream user-agent contract fails closed before thread access.
- Ruling: Task 4 fix round 1 must bound retained event bytes end-to-end and apply backpressure without dropping mapped events — count-only double buffers amplify the valid 8 MiB wire limit into a multi-gigabyte resident set, while fully unbuffered forwarding can deadlock initialization notifications before the runtime starts consuming them — cost if wrong: lower burst throughput, bounded by a documented small fixed multiple of the 8 MiB wire limit.
- Ruling: Task 4 treats a response observed while its call is still marshaling or waiting for the writer gate as unknown/fatal because that call provably cannot have emitted a byte. Once the call owns the gate and has entered the direct write, a racing response is quarantined until the write result proves at least one byte was accepted; a zero-byte result remains fatal — this distinguishes a true pre-response from a pipe response racing a still-blocked large write — cost if wrong: a broken peer that predicts an ID before the request enters its write is rejected fail-closed.
- Ruling: Task 4 keeps generic `RPCClient.Call`/`Notify` serialization as a trusted internal transport primitive, but every Adapter method must perform allocation-free escaped-length preflight for all dynamic outbound strings, including server-derived IDs; the authoritative generic marshal still enforces the exact 8 MiB frame boundary — cost if wrong: a future internal caller outside Adapter that adds an un-preflighted untrusted aggregate could allocate its encoded size before rejection and must add its own field-specific guard.
- Ruling: an admitted reverse request publishes `unsupported-server-request`, but a second concurrent reverse request that finds the single bounded handler slot busy terminates the session before publishing another observation — the first observation already marks the active turn unsupported, while publishing the overload observation through a backpressured event queue would again block the sole reader and prevent terminal convergence — cost if wrong: overload diagnostics contain one event rather than one event per concurrent peer request.
- Ruling: server-derived thread, turn, and item identifiers are at most 4096 UTF-8 bytes, non-blank, and contain no Unicode control characters; all ingress events/snapshots and outbound Adapter arguments enforce the same invariant — real pinned identifiers are short opaque tokens, while retaining arbitrary near-frame-size IDs allows a later HTML-safe JSON encoding to amplify them sixfold — cost if wrong: a future upstream identifier format using control characters or more than 4096 bytes fails closed as incompatible.
- Ruling: snapshot decoding streams arrays and caps one snapshot at 4096 turns, 16384 items per turn, and 65536 items total; turn responses/notifications apply the per-turn cap even when items are used only for shape validation — these ceilings are far above an interactive Codex session while preventing millions of tiny JSON values from expanding into slice headers — cost if wrong: exceptionally large histories require a future paginated adapter instead of one `thread/read includeTurns:true` snapshot.
- Ruling: the Task 4 protocol-ID control-character ban covers both Unicode general categories Cc and Cf — Cc covers conventional controls while Cf covers invisible/bidirectional formatting controls such as U+200B and U+202E that can make an ID visually blank or misleading — cost if wrong: an upstream opaque ID containing a legitimate format character fails closed.
- Ruling: Task7 defines the canonical ErrStaleRecovery in room and aliases the store sentinel to it — Coordinator must return the same typed error without importing store and creating a cycle — cost if wrong: one additional domain-level exported error to maintain.
- Ruling: Task7 may extend Store.FinishTurn CAS from running to running or needs-review, while live terminal events accept running only — runtime failure marks reviewed before history reconciliation, so proven terminal history needs this transition — cost if wrong: another trusted repository caller could finalize reviewed work without equivalent history proof; terminal states remain excluded and tested.
- Ruling: completed-item history persistence accepts verified stored-thread history independent of current active binding and deduplicates immutable (thread, turn, item) payloads transactionally — repeated recovery must not allocate duplicate events and history includes prior/ambiguous turns — cost if wrong: event-table lookup may become expensive for very large histories; live Coordinator writes remain restricted to current running turn.
- Ruling: Task7 fix may amend Adapter.snapshot and its tests to enforce TurnSnapshot.Items as proven-complete items — recovery consumes this typed boundary and cannot treat in-progress payloads as immutable history — cost if wrong: conservative filtering may omit uncertain historical output until terminal evidence is available.
- Ruling: daemon caps encoded mutation bodies at 64 KiB before persistence — the 8 MiB transport limit alone cannot guarantee that enriched durable events remain replayable — cost if wrong: large pasted instructions require splitting; CLI documentation must state the cap.
- Ruling: Task9 adds Store.RepairThread as a dedicated atomic transaction with old binding, repair reason, and new binding in one durable event — existing BindThread lacks repair reason and split writes could half-apply owner repair — cost if wrong: an extra repository API to maintain; unresolved request state must remain preserved.
- Ruling: Task10 adds optional activeTurnId to runtime-snapshot and fills welcome activeTurnId from Coordinator — saved-cursor reconnect may omit the old turn-start event, so current active state must be restored authoritatively after replay — cost if wrong: one optional v1 wire field and extra welcome snapshot read; final revision-fenced snapshot remains authoritative.
- Ruling: runtime-snapshot includes its durable sequence watermark; client still renders/replays old durable events but ignores their active-turn updates through that watermark — revision fence covers transients only, so authoritative active state needs a durable fence — cost if wrong: one additional optional v1 snapshot field for client/server compatibility.
- Ruling: CLI init validates at least three distinct resolved Unix UIDs, not only three names — aliases can otherwise represent a single account — cost if wrong: setups intentionally using account aliases must provide genuinely distinct accounts; lower-level embedding API remains unchanged.
- Ruling: oversized agent output may use an explicit bounded omission/truncation record with original byte count and digest, and transient projection may report truncation within an encoded aggregate budget — all durable history and reconnect snapshots must fit the transport without silent data loss — cost if wrong: very large output is not fully available in the shared transcript and must be inspected in project/Codex artifacts; normal-sized content remains unchanged.
- Ruling: final fix wires accepted-message and thread/turn/item metadata, while M1 documents runtime failure codes/digests without promising every process exit code — complete normal/signal exit reporting needs lifecycle port changes better validated in Linux deployment — cost if wrong: operators have less detailed process-exit diagnostics until that milestone.
- Ruling: terminal recovery history must be persisted without entering current-turn projection suppression; only relevant nonterminal active-turn keys may consume that budget — final review identified a load-bearing regression that prevents normal streaming after valid large history, so this narrow correction is required to complete the authorized implementation — cost if wrong: delayed historical deltas rely on Coordinator current-turn filtering rather than retained old suppression keys.

## Final integration implementation notes

- Completed output is preflighted after compact HTML-safe JSON encoding. Oversized output uses an explicit omission record with first-observed upstream bytes and a SHA-256 of that normalized encoding; repeated history with formatting-only changes compares by digest.
- Streaming projection uses a conservative 1 MiB aggregate charge (entry overhead plus six bytes per identifier/text byte). After exhaustion, live clients and reconnect snapshots explicitly report truncation until that turn terminates. Completion suppression retains keys only and is released at terminal cleanup.
- A failed durable item/terminal write stops the coordinator and invokes the existing owner shutdown path. Startup recovery must reconcile before work can resume; no successor runs after missing evidence.
- Unexpected reverse requests and malformed mapped notifications bind to the serialized active turn, persist the unsupported/protocol reason, request interruption, and freeze dispatch until terminal evidence arrives. Interrupt acknowledgments alone do not prove termination.
- Adapter transport EOF drains accepted notifications. Explicit Adapter.Close is owned by Supervisor startup/shutdown cleanup and cancels a blocked forwarder without confusing consumer cancellation with EOF.
- M1 operational logs include accepted-message metadata and committed thread/turn/completed-item transitions. Complete process/command exit-status logging is deferred to Linux deployment; no exit code is inferred from sanitized error digests.
